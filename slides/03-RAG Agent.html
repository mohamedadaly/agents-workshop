01 · CONCEPT

What Is RAG?

Retrieval-Augmented Generation: before the model answers, look up passages relevant to the question from an external source, and hand the model that text alongside the question — instead of asking it to answer purely from what it memorized during training.

Without RAG

Question → model’s frozen training data → answer. Whatever it learned at training time is all it has — nothing to point to.

With RAG

Question → retrieve real passages → model reads them → answer, grounded in text it can cite.

01 · CONCEPT

Why We Need It

Frozen knowledge

A model only knows what was in its training data — nothing after its cutoff, and nothing private like your own PDF or docs site.

Hallucination

When it doesn’t actually know something, it guesses fluently rather than saying so — confidently wrong looks the same as confidently right.

No citations

A plain model can’t point to where an answer came from — there’s no passage behind it to quote.

Private or oversized corpora

Your company’s docs site or one specific PDF were never training data — too private, or too narrow, to have been baked in at all.

Indexing, Step by Step

The slow, one-time half of RAG — everything here happens once per (document, embedding model) pair, before a single question is ever asked.

01

Load

Every source becomes plain-text Documents — one per PDF page, one per crawled URL.

→

02

Split

Cut into ~1000-character chunks with 150-character overlap, so no sentence loses its surrounding context.

→

03

Embed

Each chunk becomes a vector via the embedding model — similar meaning lands nearby, regardless of exact wording.

→

04

Store

Chroma persists every vector, its text, and its citation to disk — keyed so it’s only ever built once.

01 · CONCEPT

Retrieval, Step by Step

The fast half, repeated on every question — no re-reading the document, no re-embedding anything but the question itself.

Amber = the question’s vector. Green = the k=4 nearest chunks returned. Gray = everything else in the index, ignored.

1 · Embed the question

The same embedding model places the question in the same vector space as every stored chunk.

2 · Nearest-neighbor search

Chroma returns the k=4 closest chunks by vector distance — semantic similarity, not keyword matching.

3 · Assemble context

Each result’s citation and text are joined into one string — the tool’s return value.

4 · Generate the answer

The model reads the question plus that context, and writes an answer quoting the citation already sitting next to the text.

02 · CODE

Where RAG Is Indexed

db_path = self._db_path(pdf_bytes, crawl_url, embedding_model)

self.vectorstore = Chroma(

    persist_directory=db_path, embedding_function=embeddings,

    create_collection_if_not_exists=True)

if self.num_chunks == 0:

    self.vectorstore.add_documents(pdf_chunks + web_chunks)

db_path is a hash of (PDF bytes, crawl URL, embedding model), under data/. The same trio reopens the existing Chroma collection instantly — change any one of them and a fresh collection builds instead of mixing with stale vectors from a different document or model.

02 · CODE

Two Sources, One Index

pdf_chunks = splitter.split_documents(PyPDFLoader(pdf_path).load())

web_chunks = splitter.split_documents(self._crawl_docs(crawl_url))

PyPDFLoader yields one Document per PDF page, so page numbers survive into chunk metadata. RecursiveUrlLoader(url, max_depth=2) crawls the docs site up to 2 links deep, one Document per URL. Both get split the same way, so rag_search never has to know which source a given chunk came from — they live in one combined Chroma collection.

How It’s Used: rag_search

results = self.vectorstore.similarity_search(query, k=4)

return "\n\n".join(f"{citation(doc)}\n{doc.page_content}" for doc in results)

k=4: embed the query, return the 4 closest chunks by vector distance — any mix of PDF and web pages. Each one comes back tagged with its own citation, built from whatever metadata it has:

02 · CODE

Steering the Agent

RAG first, always

Try rag_search before anything else — never answer from the model’s own training knowledge.

Web search, only as fallback

Only reach for duckduckgo_search when rag_search comes back empty or clearly unrelated.

Mandatory citation format

A RAG answer must end with Source: <document>, page <N> or a URL — copied verbatim from the result, never guessed.

Say so if nothing’s found

If neither tool turns up an answer, say so instead of guessing.

02 · CODE

The Prompt, Verbatim

You are a RAG agent that answers questions using an uploaded PDF and a crawled set of documentation pages, both indexed into the same rag_search tool.

NEVER answer from your knowledge.

Always try rag_search first. Only use duckduckgo_search if neither the PDF nor the documentation pages contain the answer — rag_search comes back empty, or its passages are clearly unrelated.

Whichever tool you used, always report the source: a PDF passage ends with Source: <document name>, page <N>; a documentation page ends with Source: <url> — copied verbatim, never guessed or renumbered. A web search result says plainly it came from a web search, not the indexed documents.

If none of the tools turn up an answer, say so instead of guessing.

Answer in plain language. Do not describe your search process beyond the required source citation.
